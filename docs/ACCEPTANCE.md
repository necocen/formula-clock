# 動作の確認項目

この文書は今後の検証用チェックリスト。完了を示す記録ではない。
`tests/browser.test.py` と `tests/stix2.local.test.py` に対応する確認も含む。

## 基本

新しいブラウザコンテキストで開き、STIX Two · Oldstyle / 分数が初期選択であること。
実際に使われたMathJaxのバージョン、通信先、書体、コンソール警告を記録する。
`FormulaClock.diagnostics()` と `FormulaClock.state` が確認に使える。

```js
// 日本のローカル時刻を前提とするプレビュー例
FormulaClock.preview('2026-09-08T16:39:19+09:00', true);
await FormulaClock.setDisplay({font: 'stix2', division: 'fraction'});
FormulaClock.diagnostics();
```

このAPIはDateからブラウザのローカル時刻を読む。
上の文字列で同じ表示を再現するテストのタイムゾーンはAsia/Tokyoに設定する。
既存のPlaywrightテストはその設定を使用している。

## 数字と動き

| 操作・時刻 | 確認すること |
|---|---|
| 「6と9を見る」/ 16:39:19 | `1 + 6 + 3 + 9 = 19`。STIX Twoの6/9が見本の字形になっている |
| 12:34:30 → 31 | `(12+3)×√4` から `−(1+2)+34`。HHMMの要素の同一性と色を維持 |
| 12:34:58 → 59 | `−1+2^(3!)−4` の指数へ3が縮小・移動する |
| 12:34:08で分数↔÷ | 同じASTの `12/3+4` と `12÷3+4`。分母の3が通常位置へ移る |
| 00:00:07 → 08 | 式から、淡い `00:00:08` の通常時刻表示へ。HHMMの要素を維持 |
| 08:28:54 / 08:59:05 | 過去の数字消失・記号の高さの報告例。数字が画面内にある |
| 3書体を複数回切り替える | 同じ式と時刻、同じHHMM要素。書体ごとの軸設定を混ぜない |

最初に `const original = FormulaClock.digits` を保存し、遷移後に
`FormulaClock.digits.every((el, i) => el === original[i])` を確認する。

## 高さ・画面幅

等号の2本線の外接矩形の中央が表示領域の中央にあること。
既存テストはその誤差に0.12 px未満の閾値を使う。
分数・根号によって式の外接矩形が変わっても、等号の縦位置が変わらないこと。
同じ倍率・通常位置の数字は、30→31で不要な上下移動を起こさないこと。

320 / 390 / 768 px幅とデスクトップ幅で、分数・指数・時刻表示に横スクロールや数字欠落がないこと。
`prefers-reduced-motion` 有効時も配置が正しく、アニメーションを抑制できること。

## データと括弧

`tests/browser.test.py` にある12:48:05の独自AST `1 + 2 / (4 / 8) = 5` を使い、
÷モードの `1 + 2 ÷ (4 ÷ 8)` が必要な括弧を持つことを確認する。

1分レコード・全日形式のJSON読み込み、元データへの復帰、不正JSON時に既存提供元を維持する動作を確認する。
提供元差し替え後の遅い応答を破棄すること。中止に応じない提供元も対象。
明示的nullの秒と、データ欠落・HTTP失敗・不正レコードの秒を区別し、いずれも時計表示を停止させないこと。

外部データ版はHTTPで開く。初回、分変更、23:59から00:00、取得失敗後の再試行を確認する。

## 音と操作

音を有効化して23:59:56.7から再生し、440 / 440 / 440 / 880 Hzの4イベントを確認する。
通常の毎分00秒にも時報があること。プレビュー停止中は鳴らさないこと。
音オフ、時刻変更、非表示からの復帰で古い時報を重複再生しないこと。
テストのイベントログ確認に加え、利用環境で実際の音も確認する。

Space（再生/停止）、M（音）、F（全画面）、L（現在時刻）と、時刻入力・プレビュー目盛りを確認する。
