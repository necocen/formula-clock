# 採用する数式データ

`expressions.json`はアプリに同梱・配信する正規ASTの全日データです。表示をリリースごとに再現するため、ソースと一緒にGit管理します。1分を1行にし、時刻順に並べて差分を確認できるようにしています。`examples/1234.json`と`examples/table.json`は形式説明用の固定サンプルです。

## 出典

- 生成元：four-foursから受け取った`formula-clock-verified.zip`（2026-09-10生成）
- ZIPのSHA-256：`c6c59b89e073de2fcfff15a12b918fdcab6fd96041a6be35c19eedc92b14d47a`
- 取り込み対象：`00.json`〜`23.json`。ASTとnullをそのまま保ち、フィールド順と改行だけを正規化
- 1,440分・86,400秒のうち、式あり71,686秒、通常時計14,714秒
- 受領ZIPでは一次検証71,061式、SymPy再検証625式。取り込み時にも全式の構造と値を再検証済み

JSONは約11.6MB、gzipでは約260KBです。受領ZIP・生成時の候補・却下一覧・テスト結果はGitへ重複して追加しません。作業用ファイルは`test-results/`に置きます。

## 更新方法

生成側で計算結果と定義域を検証済みのZIPを作業用ディレクトリへ展開し、24個の時間別JSONがあるディレクトリを渡してください。

```sh
pnpm run import:data test-results/imported-hours
pnpm run build
pnpm test
pnpm run test:og
```

インポートは全時間・全分・60秒・ASTの構造を検証してから書き込みます。`pnpm test`はTeX／テキストへの変換で演算構造・結合順序・数字のスロットが保たれることを確認します。式の値と途中の定義域は生成側で確認し、取り込み後のテストでは再計算しません。

外部JSONを取り込んだときは、この出典情報も更新します。ブラウザ・OG画像の分数／指数／通常時計の確認例は、新データでも該当する式がある時刻に保ってください。上のコマンドは順に実行します。`pnpm test`のビルド検証も配信ディレクトリを再生成します。

`pnpm run generate`は、この受領データを再現するコマンドではありません。リポジトリ内の探索器で全日を再探索して上書きするため、表示変更や受領データの取り込みには使いません。
