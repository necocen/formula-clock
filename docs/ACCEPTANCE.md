## 基本

新しいブラウザコンテキストで開き、STIX Two · Oldstyle / 分数が初期選択であること。
実際に使われたMathJaxのバージョン、通信先、書体、コンソール警告を記録する。
`FormulaClock.diagnostics()` と `FormulaClock.state` が確認に使える。

```js
// 日本のローカル時刻を前提とするプレビュー例
FormulaClock.preview('2026-09-08T16:39:19+09:00', true);
await FormulaClock.setDisplay({ font: 'stix2', numerals: 'oldstyle', division: 'fraction' });
FormulaClock.diagnostics();
```

このAPIはDateからブラウザのローカル時刻を読む。
上の文字列で同じ表示を再現するテストのタイムゾーンはAsia/Tokyoに設定する。
既存のPlaywrightテストはその設定を使用している。

## 数字と動き

| 操作・時刻                        | 確認すること                                                 |
| --------------------------------- | ------------------------------------------------------------ |
| 設定の時刻指定 / 16:39:19         | `1 + 6 + 3 + 9 = 19`。STIX Twoの6/9が見本の字形になっている  |
| 12:34:30 → 31                     | `(12+3)×√4` から `−(1+2)+34`。HHMMの要素の同一性と色を維持   |
| 12:34:58 → 59                     | `−1+2^(3!)−4` の指数へ3が縮小・移動する                      |
| 23:59:10で分数↔÷↔/                | 同じASTの `(2+3)/5+9`、`(2+3)÷5+9`。分母の5が通常位置へ移る  |
| 00:00:07 → 08                     | 式から、淡い `00:00:08` の通常時刻表示へ。HHMMの要素を維持   |
| 08:28:54 / 08:59:05               | 過去の数字消失・記号の高さの報告例。数字が画面内にある       |
| 4書体×数字2種類を複数回切り替える | 同じ式と時刻、同じHHMM要素。組み合わせごとの軸設定を混ぜない |

最初に `const original = FormulaClock.digits` を保存し、遷移後に
`FormulaClock.digits.every((el, i) => el === original[i])` を確認する。

設定には字体4種の選択欄と、数字2種類・除算3種類（分数・÷・/）のセグメントコントロールがあること。日本語・英語とも、数字は横一列の2等分、除算は横一列の3等分で、320px幅でも折り返さず文字が各区画内に収まること。両方ともクリック・タップ・左右キーで選択し、選択状態とフォーカスが分かること。字体のみの変更で数字スタイルを変えず、再読み込み後も両方を復元すること。
旧保存設定はEuler→Lining、STIX Two→Oldstyleへ移行すること。

## 高さ・画面幅

右上のボタンは設定・音・全画面・共有の順に表示し、Tabのフォーカス順も一致すること。共有の手前だけ余白を広げ、320px幅でも見出しや各ボタンと重ならないこと。

全書体のLiningで0の実字形の中心へ四則記号・等号・数式軸を合わせ、Oldstyleは書体本来の軸を使うこと。
切り替え後も両スタイルで本来の字形を使い、小さい時計と数式の数字を一致させること。

既存テストはその誤差に0.12 px未満の閾値を使う。

同じ倍率・通常位置の数字は、30→31で不要な上下移動を起こさないこと。

320 / 390 / 768 px幅とデスクトップ幅で、分数・指数・時刻表示に横スクロールや数字欠落がないこと。
`prefers-reduced-motion` 有効時も配置が正しく、アニメーションを抑制できること。

## データと括弧

08:58:46の根号全体に付く階乗は、画面・OG画像でも根号全体を括弧で囲み、`!`を閉じ括弧の外に置くこと。根号内の`0!`と区別でき、テキストと同じ適用範囲を示すこと。

02:20:33の累乗の底にある二重根号を、画面・OG画像で括弧なしに表示すること。指数20が両方の根号の上線の外にあり、根号の内側の累乗と区別できること。タイトル・Descriptionなど上線のないテキストでは、意味を保つための括弧を残すこと。

`tests/browser/clock.test.ts` にある12:48:05の独自AST `1 + 2 / (4 / 8) = 5` を使い、
÷モードの `1 + 2 ÷ (4 ÷ 8)` と / モードの `1 + 2 / (4 / 8)` が必要な括弧を持つことを確認する。選択は保存・復元され、KV共有ページとOG画像でも同じ除算スタイルになること。

設定画面には式データの読み込み・復元ボタンやファイル入力がないこと。APIによる提供元の差し替えは動作すること。
提供元差し替え後の遅い応答を破棄すること。中止に応じない提供元も対象。
明示的nullの秒と、データ欠落・HTTP失敗・不正レコードの秒を区別し、いずれも時計表示を停止させないこと。

外部データ版はHTTPで開く。初回、分変更、23:59から00:00、取得失敗後の再試行を確認する。

## 音と操作

通常の秒は2000 Hz / 7 ms、27・28・29秒と57・58・59秒は500 Hz / 50 ms、10秒ごと（00秒を含む）は1000 Hz / 1350 msを鳴らすこと。
各秒の開始時に複数種類の音を鳴らさず、短音は素早く切れ、時報音は余韻を伴って減衰すること。時報の余韻中も次の秒音は通常どおり鳴らすこと。
23:59:56.7から再生し、500 / 500 / 500 / 1000 Hzの予告・時報と、その後の2000 Hzの秒音を確認する。
プレビュー停止中と左右キーによる秒移動では鳴らさず、現在時刻へ戻ると正しい秒の時報を再開すること。
音オフ、時刻変更、非表示からの復帰で古い時報を重複再生しないこと。
時報のオン／オフと音量（0%を含む）を保存・復元し、不正な保存値や保存領域のエラーでも時計を使えること。
保存されたオン状態は自動再生が止められても維持し、クリック・キー操作で再開すること。復元時は確認音を鳴らさないこと。
音の再開待ちの間にオフにしたら、遅れて再開応答が届いてもオフのままにすること。
`state.soundEnabled`は選択したオン／オフ、`state.soundReady`は実際の再生可能状態、`state.soundVolume`は0〜1の音量を示す。
テストのイベントログ確認に加え、利用環境で実際の音も確認する。
`tests/browser/audio.test.ts` は1分全60音のWeb Audio生成、波形の周波数・長さ・減衰、音量・停止中の秒移動・現在時刻への復帰を検証する。
`tests/browser/audio-settings.test.ts` は保存復元、再生待ちからの再開、待機中のオフと非同期応答の競合を検証する。

Space（表示中の秒で一時停止／現在時刻へ戻る）、← / →（一時停止中に1秒移動）、M（音）、F（全画面）、L（現在時刻）と、時刻入力・プレビュー目盛りを確認する。
操作欄には左右キーの案内と「現在時刻へ」だけを表示し、再生・速度変更ボタンを置かない。左右キーで分・日付の境界を往復でき、連打でも要求した秒数ぶん移動すること。目盛りのボタンにフォーカスがあっても左右キーで移動できること。入力欄・設定や共有ダイアログ・修飾キー付きの操作には干渉しないこと。Spaceの長押しは一度だけ切り替え、ボタンにフォーカスがあるときは通常のボタン操作を保つこと。
全画面に対応し、ブラウザが許可する環境だけ全画面ボタンを表示すること。非対応時に見た目だけの状態へ切り替えないこと。
全画面への移行・終了は実際の`fullscreenElement`で確認し、ボタンの状態と一致すること。要求が拒否された場合はメッセージを表示すること。
全画面では数式の表示領域が広がり、短い式も通常表示より大きくなること。文字サイズの上限は160px（通常表示は112px）とし、4Kなどの大画面でも拡大し続けないこと。分数・指数・通常時計が領域内に収まり、等号の軸と数字要素を保持すること。終了後は元の大きさへ戻り、横長の低い画面でも操作ボタンが画面内に収まること。

## アイコン・等号・小さい時計

ライセンスは設定からモーダルで開く。閉じるボタン・外側クリック・Escapeで設定へ戻り、
フォーカスはライセンスボタンへ戻る。本文は小さい画面で内部スクロールできること。
設定内のGitHubリンクが `https://github.com/necocen/formula-clock` を指すこと。
時報ボタンはアイコンのみで、オン／オフを形・色・aria-pressedで識別できること。

等号のSVG要素と字形を数式間で保持し、数字と同じ補間で移動すること。
移動中も等号の実字形中央が固定の数式軸に一致し、古い等号のフェードと重複しないこと。
式なしの時計表示では等号を隠し、数式へ戻れば再表示すること。
上の小さい時刻は数式表示時だけ表示し、秒の文字サイズを時・分と揃える。
上も選択中の書体と数字スタイルで描くこと。幅の広い数字があっても桁同士が重ならず、桁・コロンの位置と時分秒の大きさを揃えること。

表示・非表示は300msでフェードすること。
途中で切り替えても現在の濃さから自然に反転し、reduced-motionでは即時に切り替わること。
非表示でも領域の高さを維持し、数式／通常時計の位置を動かさないこと。

## 実験機能：記号の移動

初期設定はオン。設定のチェックボックスで切り替わり、リロードしても設定を保持すること。
4書体×Lining / Oldstyle、分数 / ÷ の両方で、オン／オフによる数字の配置差が0.12px未満であること。
`＋ − × ÷ !` が同じ持ち場に残る場合はグループと字形を保持し、数字と同じ時間で移動・拡縮すること。
12:34:30→31で共通の＋が消えずに移動し、不要な×だけが消えること。
16:39:19→12:34:31で3個の＋のうち2個を再利用すること。
高速プレビュー、式なし表示、設定切り替え後に記号が重複・残留しないこと。
reduced-motionでは即座に配置し、フェードしないこと。分数線・括弧・根号は対象外。

`tests/browser/symbol-motion.test.ts` が、配布経路のフォントで配置一致・要素寿命・設定保存を検証する。

記号の持ち場は画面座標ではなくHHMMスロットで判定する。
`1−2＋3＋4` → `1＋2−3＋4` では最初の−と＋を再利用せず、末尾の＋だけを保持すること。
`1＋2＋3!＋4` → `1＋2＋3＋4!` では階乗を付け替えて移動させず、古い階乗を消すこと。
同じ3に付く階乗は、式の配置が変わっても保持すること。
単項マイナスと減算は同じ字形でも別の役割として扱う。多重階乗の内側・外側を交換しないこと。

`structureMotion` は初期値オンで、`symbolMotion`がオンの場合に有効にできること。設定・保存・リロードが機能すること。

## UIの言語

- ブラウザの最優先言語が`ja`・`ja-JP`なら日本語、`en-US`・`fr-FR`など日本語以外なら英語になること。優先言語の2番目以降に日本語があっても英語から切り替えないこと。
- 設定・詳細・共有・プレビュー・時報・全画面のラベル、通知、aria-labelが選択言語に揃うこと。日本語UIでも「フォント」「LICENSE」「Loading」を使うこと。復帰ボタンは「現在時刻へ」とし、Spaceの一時停止／現在時刻への復帰と左右キーの1秒移動を説明すること。
- ライセンス画面の説明は常に日本語とし、ライセンス原文は翻訳・変更しないこと。見出し・閉じる操作だけ共通UIとして扱うこと。
- `html.lang`が`ja`または`en`となり、320/390px幅で英語ラベルが操作を押し出さないこと。
- UI言語で時刻・AST・書体・桁の要素・音・保存済み設定・共有URLの内容を変えないこと。単体HTMLでも同じ言語選択を使うこと。

## 共有とOG画像

- 初回の描画・データ取得中と取得／描画エラー中は共有ボタンを無効にする。KVから復元した表示は現在の式データが取得不能でも描画・共有できる。
- 共有操作は表示中の秒・表示設定・ASTを同期的に停止・確定し、ID発行後に英数字10文字の`/s/<ID>`を共有する。KV保存を止めたテストでもAPIが202で先にIDを返し、解除後に同じIDへ期限なし保存されること。`-`・`_`や表示パラメータのクエリを含めない。
- ネイティブ共有をユーザー操作の有効期間内に呼び、カードと同じ`Formula Clock - HH:MM:SS`を`title`、共有URLを`url`としてブラウザから直接渡す。式の有無によらず`text`は渡さない。ID発行中の通知は表示せず、失敗時とコピー完了は通知する。ID発行の通信に時間がかかり有効期間を過ぎた場合とネイティブ共有失敗時は、選択済みURLと共有・コピー操作を表示する。非対応ではコピーを試し、コピー失敗は同じURL画面へ進む。キャンセルは静かに停止状態を保つ。
- ID発行失敗は再試行でき、時刻や設定の変更後に遅れた共有処理がURL表示・コピーをしない。同じ画面の再共有は既存URLを再利用する。受理後のKV保存は`waitUntil`で続き、失敗時は同じID・内容で最大3回試行し、成否をログに残す。
- 一時停止後と共有ボタンへのホバー・フォーカス・押下でURLを先行発行する。先行発行で時計やURLを変えず、ボタンを無効化しない。発行済みならクリックと同じイベント内でネイティブ共有を呼び、発行中なら要求を重複させない。
- 通常の秒更新や長時間のホバーでKVへ連続保存しない。秒をまたいだクリック、明示的なnull、設定・AST変更でも完全一致した発行済みURLだけを使う。先行発行の失敗は通知せず、クリック時に再試行する。
- 共有URLを開いた最初の表示から時刻・書体・数字・除算・式木を復元し、受信側の保存設定を上書きしない。時差や夏時間でHHMMSSを変えない。
- 現在の式データと異なる式木と明示的なnullを、初回表示・リサイズ・表示設定変更で保持する。時刻操作で現在データへ戻る。
- 左右キーによる秒移動・秒／時刻指定・現在時刻への復帰・表示設定変更時に、ページ再読み込みや履歴追加をせずURLを`/`へ戻す。数字の常設要素と時報の重複防止を保つ。
- 320px幅でも共有ボタンを含むヘッダーが画面内に収まる。
- JavaScriptなしでHTMLにOG・Twitter Cardとcanonicalがあり、共有ID間でメタデータが混ざらない。カードタイトルは`Formula Clock - HH:MM:SS`、Descriptionは`-(2×3)+50=44`のような式（乗算`×`、除算`/`、累乗`^`）。ネイティブ共有の`title`がカードと一致し、`text`は渡さない。ページのタイトルは`1 + 2^3 / √4 = 5`のように不要な括弧を省く。入れ子の除算・累乗・負号・階乗では意味を保つための括弧を残し、`(√4)^2`と`√(4^2)`を区別する。旧クエリURLも読み込める。
- `og-snapshots`プロジェクトの固定PNG比較が通ること。意図した見た目の変更だけ、差分を目視して基準画像を更新する。実際の画像・差分はPlaywrightのレポートに残す。
- PNGは1200×630。左上のロゴはサムネイルで読める大きさとし、数式・淡い時計との間隔を保つ。
- 4書体×Lining / Oldstyle×分数 / ÷で、字形パス、分数・指数・大型根号、数字の色、固定した等号の軸、欠けのなさを確認する。
- R2未保存時の生成、保存済み画像の再利用、削除後の再生成、描画版更新、同時要求を確認する。
- 同じ時刻・設定でASTが違うIDの画像を区別し、R2削除後も保存済みASTから再生成する。未知IDやKV障害で現在の式を表示しない。
- 失敗時は同梱ロゴPNGを短時間キャッシュで返し、正常画像としてR2に保存しない。R2書き込み失敗だけなら生成したPNGを返す。
